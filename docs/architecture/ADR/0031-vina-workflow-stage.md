# ADR-0031: Expose the existing Vina handler as a workflow stage

- **Status:** Accepted
- **Date:** 2026-09-25
- **Context:** The existing Vina + Meeko implementation already prepares receptor and ligand PDBQT inputs, runs Vina, and returns normalized pose/result contracts. The stage-handler registry introduced for workflow execution needs to expose this capability without putting Vina process details into the scheduler.
- **Decision:** Register a `docking` / `vina` provider through the `caddsuite.stage_handlers` entry-point group. Its factory takes explicitly configured paths to Vina, the Meeko interpreter, and Meeko scripts; probes executable and Meeko versions with fixed argv and `shell=False`; then constructs the existing handler. It advertises normalized `Compound`, `CompoundForm`, `Conformer`, `PreparedReceptor`, `Structure`, and `BindingSite` inputs and a `DockingResult` output. The handler records hashes for calculation inputs and can declare CPU and memory requirements.
- **Scientific boundary:** This stage accepts a prepared receptor, a hash-linked ligand conformer, and an explicit binding-site definition. It does not infer a binding site, prepare/protonate the protein, generate ligand conformers, or guarantee MD compatibility. Complex preparation and force-field/topology validation remain separate stages. A docking result is not an MD-ready system.
- **Consequences:** The scheduler discovers docking capability without importing or probing a specific engine. Vina and Meeko versions are recorded by the handler/runtime provenance path. Engine installation paths are configuration, not core constants. A future docking implementation can register another `(kind, engine)` capability while satisfying the same normalized output expectations. The current plugin/runtime path has registry contract tests; the real Vina engine regression still invokes the handler directly, so a Vina execution-through-runtime provenance integration test remains required before this migration is declared complete.
- **Validation:** `tests/unit/test_stage_handler_registry.py` checks Vina registration, contract declarations, and installed entry-point discovery. `tests/unit/test_vina_handler.py` real-engine integration passed with the isolated Vina/Meeko environment and verifies normalized poses plus complex construction. Full default suite: 500 passed, 32 skipped; strict mypy: 162 source files; frozen legacy manifest: 143/143.
