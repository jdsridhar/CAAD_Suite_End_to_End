# ADR-0033: Import legacy projects as bounded provenance-partial activities

- **Status:** Accepted
- **Date:** 2026-09-26
- **Context:** The independent docking and MD applications leave useful project directories, results and logs, but do not preserve complete provenance. MD projects may contain gigabytes of trajectories, and a configured target (for example TARGET_NS=100) is not proof the run completed that duration. Folder names are not stable compound or target identity.
- **Decision:** Provide read-only project inspection and a bounded import operation. Parse allowlisted project.conf values as literal data, never shell. Select supported files under per-file and aggregate size limits, hash while copying to the content-addressed store, and report excluded entries. Preserve parsed log/MDP observations without treating them as complete science contracts. Emit a versioned LegacyImportReport with completeness=partial, and persist the present-day importer itself as a TaskAttempt that uses imported source artifacts and generates the report artifact. Do not fabricate a historical engine attempt or infer Compound, Target, Pose or MDSystem identities from names.
- **Consequences:** Re-importing an unchanged inventory is idempotent. Raw legacy data stays inspectable; imported output is linked through artifact hashes and a real importer activity. Trajectory binaries and repeated production coordinate snapshots are omitted by default and explicitly reported; their bytes are outside the inventory digest. The source directory remains read-only.
- **Alternatives:** Import every file unconditionally (rejected: can copy multi-gigabyte trajectories and fill storage); create a successful historical MD/docking TaskAttempt with guessed host/version/commands (rejected: false provenance); infer compounds from filenames (rejected: collisions and chemical identity ambiguity).
- **Validation:** Synthetic Docking and MD source fixtures test safe literal parsing, path escape rejection, bounded file selection, version/MDP observations, report artifacts, provenance edges and idempotency. Read-only plans were exercised on actual `test_docking` (156 result rows, 47 MB selected) and `5NIU_LIG` (57 MB selected; both GROMACS 2025.1 and 2026.3 observed). No actual user project was imported during development.
