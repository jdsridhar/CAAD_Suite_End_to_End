# G-MD-67 — PME versus cutoff backend sensitivity control

**Finding:** In the G-MD-44 matched-coordinate reruns, the large CPU/GPU Potential shift observed with PME is not reproduced when Coulomb electrostatics use a plain cutoff. Across the same 15 selected frames (three replicas, 100–500 ps), GPU minus CPU mean Potential is **+0.012448 kcal/mol** for cutoff versus **+1.381503 kcal/mol** for PME. The corresponding Coulomb (SR) differences are +0.007469 and +1.374781 kcal/mol. This points toward an Ewald/PME-specific path or its interaction with the nonbonded kernels; it does not by itself identify reciprocal-exclusion correction as the cause.

## Method

Created an energy-only control TPR from the retained G-MD-44 energy MDP, original `npt.gro`, and original `topol.top`. The only electrostatics-model change was `coulombtype=PME` to `Cut-off`; PME-only grid and tolerance settings were removed. The derived MDP SHA-256 is `c7a360d48672d075881999c254b53120c3c69e073d24c5c372d08f836b041a44`; source and change list are in the external derivation record.

Reran the identical three retained whole-molecule TRRs with GROMACS 2026.3, CPU PP (`-nb cpu`) and GPU PP (`-nb gpu -gpu_id 0`), one MPI rank and four OpenMP threads. No dynamics were advanced; rerun coordinates were evaluated only. The GPU logs report the short-range PP task on the GPU, while the update task remains CPU because rerun does not support GPU update. `gmx energy` selected Coulomb-14, Coulomb (SR), and Potential. The comparison uses 100–500 ps, omitting the initial frame, and reports first backend minus second backend in kcal/mol.

| Electrostatics control | Contrast | n | Potential (kcal/mol) | Coulomb (SR) (kcal/mol) |
|---|---|---:|---:|---:|
| PME (G-MD-65) | GPU − CPU | 15 | +1.381503 | +1.374781 |
| Plain cutoff (G-MD-67) | GPU − CPU | 15 | +0.012448 | +0.007469 |

Cutoff GPU−CPU Potential frame differences range from −0.063486 to +0.085893 kcal/mol (RMSE from zero 0.048462); Coulomb (SR) ranges from −0.067220 to +0.082158 kcal/mol. These are descriptive differences on correlated frames, not statistical uncertainty estimates. Coulomb-14 was identical across the two cutoff backends for all selected frames.

## Interpretation and limits

- The roughly 111-fold difference between the PME and cutoff mean backend Potential shifts is evidence against a similarly large generic CPU/GPU offset for this system and these trajectories. It increases the likelihood that the PME/Ewald implementation path, or its coupling to PP evaluation, is involved.
- This is not an isolated toggle of reciprocal-exclusion correction: switching from PME to plain cutoff removes reciprocal electrostatics and changes the short-range Coulomb functional and neighbor-list workload. Therefore ordinary direct-space accumulation, exclusions, PME screening, and arithmetic/precision interactions are not separately identified.
- Plain cutoff electrostatics can produce artifacts and is used only as a diagnostic control. It is not a physical-model recommendation or a replacement for PME.
- Only one pose-derived system and 15 temporally correlated frames were examined. No correction, tolerance, Amber/GROMACS compatibility profile, or general CPU/GPU equivalence is inferred. Amber attribution remains on hold until the discrepancy is understood under a fixed backend and independent configurations.
- GROMACS `mdrun` logged that the rerun update task is unsupported on GPU; it also explicitly assigned the non-perturbed short-range PP task to GPU. The control therefore compares CPU versus GPU PP execution with CPU-side rerun/update handling, not an all-GPU trajectory update path.

To reproduce the cutoff reruns (run from each replica's own output directory):

```bash
gmx mdrun -s /path/to/energy-cutoff.tpr -rerun /path/to/prod-whole.trr \
  -deffnm rerun -nb cpu -ntmpi 1 -ntomp 4 -pin off
# or use -nb gpu -gpu_id 0 for GPU PP
```
