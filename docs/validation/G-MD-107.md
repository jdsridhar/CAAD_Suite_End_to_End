# G-MD-107 — Matched Amber Sander/GROMACS forces across three existing replicas

**Result:** Recomputed GROMACS forces on the same 15 saved 5NIU/RC8 coordinates used by the Amber restart frames, then compared them with AmberTools Sander forces at those exact coordinates. Across three independent-velocity replicas and five saved frames per replica (100–500 ps), all-frame coordinate identity was confirmed under periodic minimum-image comparison. Mean all-atom force component RMS difference was 0.010820 kJ mol⁻¹ Å⁻¹ (0.01786% of the Sander component RMS); mean ligand-heavy-atom component RMS difference was 0.005541 kJ mol⁻¹ Å⁻¹ (0.005855%). This supports close force agreement for this one Amber protein–ligand system and these matched settings. It does not qualify a general Amber/GROMACS profile, set an acceptance tolerance, resolve the energy residual, or validate production dynamics.

## Why the input trajectory matters

The Amber whole-molecule restart frames in `amber-inputs-whole/` were generated from `replica-N/energy-whole-rerun.trr`. An initial diagnostic mistakenly used `prod-whole.trr`; that trajectory does not contain the same coordinates and was discarded. All reported force reruns use `energy-whole-rerun.trr` and all 15 coordinates were checked against their paired Amber restart using periodic minimum-image differences before any force comparison.

Maximum coordinate RMS across the 15 pairs was 1.97×10⁻⁷ Å; maximum componentwise absolute periodic coordinate difference was 6.76×10⁻⁶ Å. The RMS metric verifies the same atom ordering and physical configuration to stored-coordinate precision. The validation script requires RMS below 10⁻⁴ Å and maximum component difference below 10⁻³ Å for every frame.

## Force comparison

GROMACS forces are taken directly from the force-bearing TRR generated by `mdrun -rerun`. The TPR uses CPU particle-particle and CPU PME evaluation, one MPI rank × four OpenMP threads, the existing Amber-derived GROMACS topology, no constraints, a 60×81×48 PME grid, fourth-order interpolation, 1.0 nm cutoff, and no analytical dispersion correction. No dynamics were integrated. The matching Amber force calculation used the hash-identified Amber prmtop, Sander PME, 10 Å cutoff, periodic boundaries, `ntc=1`, `ntf=1`, and no restraints. Sander gradients in kcal mol⁻¹ Å⁻¹ were converted to kJ mol⁻¹ Å⁻¹. Ligand-heavy atom indices were selected from the Amber topology's `LIG` residue and atomic numbers.

The frames are temporally correlated snapshots from three simulations of the same molecule/parameterization and are not 15 independent chemical systems or a basis for a confidence interval.

## Interpretation and limits

G-MD-44 reports a mean GROMACS-minus-Sander potential-energy difference of −2.438 kcal/mol over these same three short replicas. The force-vector agreement indicates that this energy offset does not correspond to a comparably large instantaneous force disagreement at the tested configurations. It does not identify the source of the energy difference; energy-component and convention analysis remains necessary. Force similarity at saved coordinates alone does not show that two engines will generate equivalent trajectories, sampling, or free-energy estimates.

The Sander Python API total-energy values written alongside this force diagnostic were not used for the energy interpretation. At the same 15 restart coordinates, API totals were 294.03–297.79 kcal/mol below the retained Sander CLI totals (mean −296.07 kcal/mol). A controlled CLI energy-only evaluation at replica 1, 100 ps, with the 60×81×48 PME grid showed that changing CLI `vdwmeth` from 0 to 1 lowered the van der Waals component by 294.6120 kcal/mol (6547.0379 to 6252.4259); electrostatic CLI EEL stayed −70030.9550 kcal/mol. At that same frame the API returned identical total, VDW, and EEL values for `vdwmeth=0` and `vdwmeth=1`; its VDW value (6252.425927 kcal/mol) matches the CLI `vdwmeth=1` value to printed precision. Thus the large API/CLI offset on this fixture is explained by the API behaving as if the analytical VDW correction were active regardless of that API field. A remaining ~0.025 kcal/mol EEL difference is consistent with a small PME/backend or rounding difference and is not yet attributed. Use CLI `vdwmeth=0` values for the G-MD-44 cross-engine energy comparison; do not combine API energies with them.

This is one 5NIU/RC8 topology and force-field conversion, one GROMACS version/build, one CPU backend, and one set of PME settings. There is no independent analytical force reference, no accepted tolerance, no new MD, and no Amber/GROMACS compatibility qualification. Keep the Amber profile disabled pending independent chemical systems, energy-convention reconciliation, trajectory-level consequences, and a scientifically justified acceptance policy.
