# Project reproducibility export format (Phase 15.1)

## Current-state findings

- Project metadata is stored in SQLite; project-owned input artifacts are linked through
  `project_artifacts`.
- Scientific artifacts live in the content-addressed SHA-256 store. Provenance traversal can
  gather artifact ancestry, attempts, and generated/used edges for a project's workflow runs.
- Engine environment lock files are registered as artifacts and linked to task attempts.
- API run submissions retain the submitted workflow and normalized inputs in
  `run_submissions.payload`.
- The local CLI `caddsuite run` currently records hashes of its workflow and input manifest,
  but does not retain those source bytes or their paths. Such historical runs cannot be
  faithfully reconstructed from the database alone.
- Project rows do not currently model a target entity directly; export must include linked
  contracts/artifacts and run payloads rather than inventing missing target metadata.

## Package layout

The export target is a directory named `<slug>.caddsuite/`, written through a temporary
sibling directory and atomically renamed only after all included artifacts pass hash
verification.

```text
<slug>.caddsuite/
  manifest.json
  project.json
  runs/<run-id>/run.json
  provenance/project.json
  artifacts/sha256/<first-two>/<next-two>/<sha256>
  environments/locks/<sha256>.txt
  omissions.json
```

`manifest.json` carries a format version, project identity, export time, export mode,
and a sorted inventory of every package file with byte size and SHA-256. Artifact IDs,
roles, media types, producers, and source hashes remain metadata in the manifest. Filenames
are package-relative and generated by the exporter; user-provided names never become paths.

## Full and slim exports

A full export includes every project-linked artifact and every artifact reachable in project
provenance. A slim export omits only artifacts explicitly classified as large trajectory
payloads by artifact metadata. It retains the omitted artifact's identity, role, media type,
size, hash, producer, and omission reason in `omissions.json`. An artifact without reliable
classification is included; the exporter must not guess from an extension alone.

Workflow submissions, normalized input contracts, provenance, logs, reports, and environment
locks are not omitted by slim mode. Missing workflow/input source bytes are reported as
reproducibility gaps. The export is still useful as an archive but must not be labeled
self-contained or replayable when those bytes are absent.

## Integrity and privacy rules

- Verify every source blob against its SHA-256 before copying and verify the copied package
  inventory before publishing the export directory.
- Reject symlinks and path escapes; use fixed package paths and streamed copying for large data.
- Never copy the entire SQLite database: it contains unrelated projects and local scheduler
  state.
- Preserve original provenance payloads as JSON with stable key ordering; do not rewrite or
  synthesize scientific results.
- Keep timestamps and host/environment facts because they are provenance, while treating
  export time as packaging metadata rather than calculation time.
- Include proprietary engine lock metadata as user-provided environment evidence only; do not
  bundle licensed engine executables or redistributable packages that violate their licenses.

## Implementation sequence and gate

1. Persist or attach workflow and input-manifest bytes for new CLI runs so they are exportable.
2. Implement a project-scoped exporter over project rows, run submissions, provenance graphs,
   project artifact links, and the content-addressed store.
3. Add `caddsuite project export PROJECT_ID --output PATH [--slim]`.
4. Test full/slim membership, unrelated-project isolation, deterministic inventory ordering,
   hash mismatch/missing blobs, atomic failure cleanup, and unsafe output/path handling.
5. Validate a full export by opening it in a fresh temporary data root and comparing project,
   run, provenance, and artifact identities; until replay exists, call this archive validation,
   not a complete reproduction gate.
